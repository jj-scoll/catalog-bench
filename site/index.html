    Peak is the median commits per second across repetitions at the writer count where that median is highest. The other columns describe the same writer count. Catalog call share is the part of the median commit time spent in the catalog call, for systems that report it; the rest is spent in the client. Verified means every acknowledged commit was found afterwards, in every run.

    Do all writers get a turn?

    Each bar runs from the writer that got the fewest commits to the one that got the most, on a scale from zero to the most. A short bar at the right end means the writers shared evenly; a long bar means some were starved. Compare the slowest commit with the median beside it.

    What each entry measures

    Method

    N writer processes each open their own connection and commit one single-row insert at a time, as fast as the system acknowledges them, for a fixed period. A commit counts only when the client was told it succeeded.

    A run is marked verified when the rows found afterwards equal the acknowledged commits, allowing for failed commits that landed anyway.

    Single-row commits are the worst case for a catalog on purpose: they isolate commit cost from data volume. Batched and multi-table workloads are planned.

    Results from a workstation or a shared CI runner are noisy. Compare systems within one run on one machine, not across machines. That is why each environment here has its own ranking, and why runs shorter than 30 seconds or with a single repetition are labelled as not comparable.

    The Python client's cost is negligible for the systems measured so far (checked against pgbench for Postgres). That has not been checked for Iceberg clients.

    Add your catalog

    Copy bench/systems/postgres.py to a new file in the same directory and edit it. Any module there with a System class is registered automatically. If the system needs a service, add it to compose.yaml.

    • Use default settings. If you tune something, make it a separate entry whose name and docstring say what changed.
    • commit_one must not return until the commit is durable by the system's own definition, and must raise if it failed. No client-side batching or retries beyond what the client library does by default.
    • State what the client is. For systems where the client does real work per commit, the client is part of the result.

    The results format is the contract: a driver written in any language can produce it for the same workload. The full interface is in the README under "Add a system". Open the repository
